ศัพท์ของ Next.js เปลี่ยนไปเรื่อย ๆ ตามแต่ละเวอร์ชัน — "Router Cache" กลายเป็น "Client Cache", `middleware.ts` กลายเป็น `proxy.ts`, caching model ที่เคยสร้างจาก segment-config exports กลายเป็น flag เดียวคือ `cacheComponents` เวลาอ่านบทเรียนแล้วเจอคำที่ไม่คุ้น หรือไม่แน่ใจว่ายังใช้ได้อยู่ไหม ให้กลับมาดูที่นี่ เราคง term ภาษาอังกฤษไว้ตามที่ developer ใช้จริง แล้วอธิบายความหมายเป็นภาษาไทย

## A–C

| Term | ความหมาย | บทเรียน |
|------|---------|--------|
| action ID | compiler ของ `'use server'` แทนที่ implementation จริงของ Server Action ในฝั่ง client bundle ด้วย action ID ที่เข้ารหัสไว้ บวก dispatcher ที่ POST กลับไปหา server ID นี้คือ endpoint สาธารณะจริง ๆ — ใครก็ตามที่ส่ง POST request แบบเดียวกันเรียกมันได้ ไม่ว่าจะเคยโหลด UI ของเราหรือไม่ ดังนั้นทุก action ต้อง authorize และ validate ด้วยตัวเอง | [Server Actions คืออะไร](/nextjs/th/server-actions-and-mutations/what-are-server-actions/) |
| AGENTS.md | ไฟล์ที่ `create-next-app` เขียนให้ที่ root โปรเจกต์โดย default (หรือด้วย flag `--agents-md`) เพื่อให้ AI coding agent มีกฎที่ตรงกับเวอร์ชันปัจจุบัน ไม่ต้องพึ่ง training data ที่อาจล้าสมัย `next dev` จะเติม block ที่มันจัดการอยู่กลับเข้ามาเองอัตโนมัติ ดังนั้นการลบมันออกจาก diff โดยไม่แก้ต้นตอ จะแค่สร้าง uncommitted change กลับมาใหม่ | [การตั้งค่าโปรเจกต์และ Toolchain](/nextjs/th/foundations/project-setup-and-the-toolchain/) |
| App Router vs. Pages Router | App Router (`app/`) คือ model ปัจจุบัน สร้างบน React Server Components component เป็น Server Component โดย default และ fetch ข้อมูลแบบ inline ด้วย `async`/`await` ส่วน Pages Router (`pages/`) คือ model เก่าที่ทุก component เป็น Client Component ทั้งหมด ป้อนข้อมูลด้วย function อย่าง `getServerSideProps` — ทั้งสองยังใช้ได้ แต่ feature ใหม่จะลงที่ App Router เท่านั้น | [Next.js คืออะไร และ App Router](/nextjs/th/foundations/what-is-nextjs-and-the-app-router/) |
| boundary (`'use client'` / `'use server'`) | เส้นแบ่งที่ directive `'use client'` หรือ `'use server'` ขีดไว้ระหว่างโค้ดที่รันบน server กับโค้ดที่ถูกส่งไปที่ browser `'use client'` เป็น transitive — ทุกอย่างที่ import เข้ามาใน tree ของไฟล์นั้นกลายเป็นส่วนหนึ่งของ client bundle ด้วย — ตำแหน่งของ boundary จึงเป็นตัวตัดสินว่า browser ต้องโหลด JavaScript มากแค่ไหน | [Server และ Client Components](/nextjs/th/foundations/server-and-client-components/) |
| cacheComponents | flag ใน `next.config.ts` ที่มาแทน caching model แบบเดิมของ Route Segment Config (`dynamic`, `revalidate`, `fetchCache`, `dynamicParams`, `runtime`) ด้วย `'use cache'`, `cacheLife` และ `cacheTag` และยังเป็นวิธีเปิด Partial Prerendering ใน Next.js 16 ด้วย เมื่อเปิด flag นี้ segment-config export แบบเดิมจะทำให้ build พังด้วย error `Route segment config "…" is not compatible with nextConfig.cacheComponents` | [use cache และ Cache Components](/nextjs/th/data-fetching-and-caching/use-cache-and-cache-components/) |
| cacheHandler / cacheHandlers | config key สอง key ที่ใช้ตอน self-host ต่างกัน: `cacheHandler` (เอกพจน์) override cache แบบเก่าของ full-route/ISR ที่อยู่เบื้องหลัง `revalidatePath`/`revalidateTag`; `cacheHandlers` (พหูพจน์ เป็น object เพิ่มมาใน v16.0.0) ตั้งค่า backend ให้กลุ่ม directive `'use cache'` — มี `default` กับ `remote` เป็นต้น | [Deployment และ Self-Hosting](/nextjs/th/production-and-ecosystem/deployment-and-self-hosting/) |
| cacheLife | กำหนดว่า entry ของ `'use cache'` จะสดอยู่นานแค่ไหน จะใช้ named profile (`cacheLife('hours')`) หรือ profile ที่ตั้งเองใน `next.config.ts` ก็ได้ เป็นตัวแทนของ `export const revalidate` แบบเดิมภายใต้ `cacheComponents` | [use cache และ Cache Components](/nextjs/th/data-fetching-and-caching/use-cache-and-cache-components/) |
| cacheTag | ติด tag ให้ entry ของ `'use cache'` เพื่อให้ invalidate ได้แบบ on-demand ด้วย `revalidateTag` หรือ `updateTag` รับหลาย tag ในการเรียกครั้งเดียวได้ ดังนั้น entry เดียวมีทั้ง tag ระดับ collection และระดับ item พร้อมกันได้โดยไม่ต้องเรียกสองรอบ | [use cache และ Cache Components](/nextjs/th/data-fetching-and-caching/use-cache-and-cache-components/) |
| Client Cache (เดิมชื่อ Router Cache) | caching layer ตัวที่สี่: เก็บ RSC payload ของ route ที่เคยเข้าหรือถูก prefetch ไว้ในหน่วยความจำของ browser ทำให้กด back/forward แล้วเร็วทันที ตั้งแต่ v15 ค่า default ของ `staleTimes.dynamic` คือ `0` และถูก invalidate เมื่อ refresh หน้า, `router.refresh()`, มีการเขียน cookie หรือเรียก `revalidateTag`/`revalidatePath`/`updateTag` | [สี่ Caching Layers](/nextjs/th/data-fetching-and-caching/the-four-caching-layers/) |
| connection() | บังคับให้ prerender หยุดตรงนั้น แล้วให้ส่วนที่เหลือของ component รันเฉพาะตอน request จริงเท่านั้น ใช้กับโค้ดที่ไม่มี Dynamic API ให้เกาะ (เช่น `Math.random()` หรือ database driver แบบ synchronous) มันมาแทน `unstable_noStore`; ภายใต้ `cacheComponents` มักแนะนำให้ใช้ `io()` แทนเพราะยัง cache ได้อยู่ถ้าอยู่ใน scope ของ `'use cache'` | [Partial Prerendering](/nextjs/th/rendering/partial-prerendering/) |
| create-next-app | CLI สำหรับ scaffold โปรเจกต์ ค่า default ที่แนะนำคือ TypeScript, ESLint, Tailwind CSS, App Router และไฟล์ `AGENTS.md` — ทุก toggle ที่มันถาม (React Compiler, typed routes, `src/`, import alias) มีผลจริงที่ตรวจสอบได้กับโครงสร้างที่สร้างออกมา ไม่ใช่แค่ความต่างผิวเผิน | [การตั้งค่าโปรเจกต์และ Toolchain](/nextjs/th/foundations/project-setup-and-the-toolchain/) |

## D–I

| Term | ความหมาย | บทเรียน |
|------|---------|--------|
| DAL / verifySession() | pattern Data Access Layer ที่คอร์สนี้ใช้สำหรับ authorization: helper ชื่อ `verifySession()` ที่ทุก Server Action และ Route Handler ต้องเรียกก่อนแตะข้อมูล `verifySession()` เรียก `redirect()` เมื่อไม่มี session ดังนั้นห้ามอยู่ใน `try/catch` ที่กลืน control flow ของ redirect ใน Next.js เอง | [Pattern การทำ Authentication](/nextjs/th/production-and-ecosystem/authentication-patterns/) |
| Data Cache | layer ฝั่ง server ที่อยู่ถาวร เก็บผลลัพธ์ของ fetch ข้ามหลาย request และหลาย deploy ตั้งแต่ Next.js 15 เป็นแบบ opt-in ต่อการเรียกแต่ละครั้ง (`cache: 'force-cache'` หรือ `next: { revalidate }`) — `fetch` เฉย ๆ ไม่เขียนอะไรลง cache นี้เลย | [สี่ Caching Layers](/nextjs/th/data-fetching-and-caching/the-four-caching-layers/) |
| Edge runtime (deprecated) | environment ที่รันเล็กกว่า มีแค่ Web API ตั้งด้วย `export const runtime = 'edge'` ตั้งแต่ Next.js 16 ถูก deprecate ในฐานะ route runtime แล้ว — `next build` ขึ้น deprecation warning และ Cache Components ปฏิเสธ export นี้ตรง ๆ — แต่ยังมีใช้ต่อใน `proxy.ts` | [Route Segment Config และ Runtime](/nextjs/th/rendering/route-segment-config-and-runtimes/) |
| error.tsx / global-error.tsx / retry() | `error.tsx` คือ error boundary แบบ Client Component ที่จับ error จาก segment ที่อยู่ข้างใต้มัน — error ที่ throw ใน layout จะถูกจับโดย boundary ของ segment **parent** ไม่ใช่ของตัวเอง — และได้ function `reset()` มาไว้ลอง render ใหม่ ส่วน `global-error.tsx` จับ error ที่ root layout เองเป็นคน throw จึงต้อง render `<html>` และ `<body>` เองด้วย | [Pages, Layouts และ Nested Routing](/nextjs/th/routing-and-navigation/pages-layouts-and-nested-routing/) |
| filesystem cache | cache แบบ incremental ของ Turbopack ที่เก็บลงดิสก์ เปิดโดย default ทั้งกับ `next dev` และ `next build` ทำให้ build หรือ restart รอบต่อไปใช้ผลงานเก่าซ้ำแทนที่จะ compile ใหม่ทั้งหมด | [Turbopack และ Build Performance](/nextjs/th/optimization/turbopack-and-build-performance/) |
| forbidden() / unauthorized() | function ที่สร้างมาเฉพาะ (อยู่หลัง experimental flag ชื่อ `authInterrupts`) ที่ throw แล้ว render boundary `forbidden.tsx` หรือ `unauthorized.tsx` ที่ใกล้ที่สุด พร้อม HTTP status ที่ตรงกัน แทนที่จะใช้ `redirect('/login')` เฉย ๆ `unauthorized()` ใช้กับ "ยังไม่ล็อกอิน" ส่วน `forbidden()` ใช้กับ "ล็อกอินแล้วแต่ไม่มีสิทธิ์" | [Pattern การทำ Authentication](/nextjs/th/production-and-ecosystem/authentication-patterns/) |
| Full Route Cache | layer ฝั่ง server ที่อยู่ถาวร เก็บ RSC payload ที่ render แล้วบวก HTML ของ route ที่ render แบบ static ทำให้ request ที่ตรงกันข้าม render ใหม่ได้เลย อยู่จนกว่าจะ redeploy หรือข้อมูลข้างในถูก revalidate | [สี่ Caching Layers](/nextjs/th/data-fetching-and-caching/the-four-caching-layers/) |
| generateMetadata / streaming metadata / metadataBase / htmlLimitedBots | `generateMetadata` คำนวณ `<title>`/OG tag จาก route `params` บน server ตั้งแต่ 15.2 ผลลัพธ์จะ stream เข้าไปใน `<body>` สำหรับ browser ทั่วไป (หน้าเว็บถูกส่งไปก่อนที่มันจะ resolve เสร็จ) แต่จะ block แล้ว render ลง `<head>` สำหรับ bot ในรายชื่อ `htmlLimitedBots` (default คือ Twitterbot, Slackbot, Bingbot) ที่รัน JavaScript ไม่ได้ `metadataBase` ตั้ง base URL ที่ metadata แบบ relative (เช่น path ของ OG image) ใช้ resolve — ถ้าไม่ตั้งไว้ URL แบบ relative อาจ resolve ไปเป็น `localhost` ตอน production ได้ | [Metadata และ SEO](/nextjs/th/optimization/metadata-and-seo/) |
| generateStaticParams / dynamicParams | `generateStaticParams` คืนรายการค่าของ dynamic segment ที่จะ prerender ตอน build export `dynamicParams` ควบคุมว่าค่าที่มันไม่ได้คืนมาจะเกิดอะไรขึ้น: `true` (default) จะ render ตอนมี request จริง, `false` จะคืน 404 แทน — ภายใต้ `cacheComponents` กรณี `false` นี้เขียนแทนด้วย `notFound()` ในตัว page | [Route Segment Config และ Runtime](/nextjs/th/rendering/route-segment-config-and-runtimes/) |
| generateViewport | คู่หูของ `generateMetadata` เฉพาะเรื่อง `viewport` สำหรับค่า (เช่น `themeColor` หรือ `width`) ที่ต้องคำนวณต่อ request แทนที่จะประกาศเป็น `viewport` export แบบ static | [Metadata และ SEO](/nextjs/th/optimization/metadata-and-seo/) |
| hydration / hydration mismatch | hydration คือขั้นที่ React ผูก event handler กับ state เข้ากับ HTML ที่ server render มาแล้วใน browser mismatch เกิดเมื่อ HTML นั้นต่างจากผลลัพธ์ที่ client render ออกมา — สาเหตุที่พบบ่อยคือค่า `Date`/random, การ format locale, เช็ค `typeof window`, หรือ HTML ที่ nest ผิด — React 19 รายงานเป็น diff จริงที่อ่านได้ ไม่ใช่แค่ warning ทั่วไป | [Static และ Dynamic Rendering](/nextjs/th/rendering/static-and-dynamic-rendering/) |
| instrumentation.ts / onRequestError | `register()` ใน `instrumentation.ts` รันครั้งเดียวตอน server เริ่มทำงาน เป็นที่มาตรฐานสำหรับตั้งค่า telemetry; hook `onRequestError` รับ error ฝั่ง server ทุกตัว ส่งต่อไปยังปลายทาง logging จริงได้ — ถ้า log ลง `console` เฉย ๆ ตรงนั้น จะมองไม่เห็นทันทีที่ stdout ของ container ไม่ได้ถูกเก็บไปที่ไหน | [Deployment และ Self-Hosting](/nextjs/th/production-and-ecosystem/deployment-and-self-hosting/) |
| intercepting route | รูปแบบ route (folder prefix `(.)`, `(..)`, `(...)`) ที่ render route ที่ match ไว้ข้างใน layout ปัจจุบัน — เช่น modal ที่ทับอยู่บน feed — แทนที่จะ navigate ไปหน้าของมันเอง ความหมายของ prefix อยู่ที่ระดับ segment ไม่ใช่ความลึกของ folder จริง ๆ และ slot ของ parallel route (`@slot`) ไม่นับรวมในระดับนั้น | [Parallel และ Intercepting Routes](/nextjs/th/routing-and-navigation/parallel-and-intercepting-routes/) |
| ISR (Incremental Static Regeneration) | การ revalidate แบบ background ตามเวลาของ route ที่ render แบบ static เปิดด้วย `export const revalidate = <seconds>` ภายใต้ model Route Segment Config เดิม (หรือ profile ของ `cacheLife` ภายใต้ `cacheComponents`) | [Route Segment Config และ Runtime](/nextjs/th/rendering/route-segment-config-and-runtimes/) |

## L–N

| Term | ความหมาย | บทเรียน |
|------|---------|--------|
| loading.tsx | file convention ที่ครอบ `page.tsx` ของ segment นั้นด้วย `<Suspense>` boundary โดยอัตโนมัติ พร้อม fallback UI ที่กำหนด แสดงระหว่างที่ข้อมูลของ segment กำลังโหลด ให้ granularity การ stream แบบหยาบระดับ segment; ถ้าต้องการควบคุมละเอียดกว่านั้นให้ใช้ `<Suspense>` เองลึกลงไปใน tree | [Streaming และ Suspense](/nextjs/th/rendering/streaming-and-suspense/) |
| matcher | export `config.matcher` ใน `proxy.ts` ที่กำหนดขอบเขตว่า path ไหนบ้างที่จะรัน proxy ถ้าไม่ตั้งไว้ proxy จะรันทุก request — รวมถึง `_next/static`, `_next/image`, และ prefetch request — การเช็ค auth ที่ไม่ได้ scope ไว้จึงอาจไปบล็อก asset ของตัวเอง หรือทำงานกับลิงก์ที่ user แค่เลื่อนผ่านโดยไม่ได้ตั้งใจ | [Proxy (Middleware) และ Request Lifecycle](/nextjs/th/production-and-ecosystem/middleware-and-the-request-lifecycle/) |
| next/dynamic | wrapper รอบ `import()` สำหรับโหลด component แบบ lazy มักใช้คู่กับ `ssr: false` เพื่อโหลด dependency ที่ใช้ได้เฉพาะ browser (เช่น library canvas) โดยไม่ต้องรวมมันไว้ใน server render หรือ initial bundle | [Script และ Bundle Optimization](/nextjs/th/optimization/scripts-and-bundle-optimization/) |
| next experimental-analyze | ตัววิเคราะห์ bundle ที่ใช้ Turbopack เป็นฐาน รันด้วย `npx next experimental-analyze` เปิด UI แบบ interactive (หรือเขียนไฟล์ `.next/diagnostics/analyze` เมื่อใส่ `--output`) แสดงให้เห็นว่าใน client bundle ของแต่ละ route มีอะไรอยู่จริง — มีประโยชน์เวลาจับ boundary `'use client'` ที่วางสูงเกินไป | [Script และ Bundle Optimization](/nextjs/th/optimization/scripts-and-bundle-optimization/) |
| next/font | self-host ไฟล์ font ตั้งแต่ตอน build แล้ว inline CSS `@font-face` ให้เลย ทำให้ไม่มี request ไปหา Google Fonts (หรือที่ไหนก็ตาม) ตอน runtime และไม่มี layout shift จาก font ที่โหลดมาช้า | [Image และ Font](/nextjs/th/optimization/images-and-fonts/) |
| next/image (sizes, remotePatterns, minimumCacheTTL) | component รูปภาพในตัวที่ resize, แปลง format, และ lazy-load ให้โดยไม่มี layout shift `sizes` บอก browser ว่าที่แต่ละ breakpoint ควรใช้ความกว้างเท่าไร (ถ้าตั้งผิด browser จะโหลดรูปใหญ่เกินจำเป็น); `remotePatterns` คือ allowlist ของ host รูปภาพภายนอก; `minimumCacheTTL` คือเวลาขั้นต่ำที่รูปที่ optimize แล้วถูก cache ไว้ เปลี่ยนจาก 60 วินาทีเป็น 4 ชั่วโมง (14400 วินาที) ตั้งแต่ Next.js 16 | [Image และ Font](/nextjs/th/optimization/images-and-fonts/) |
| NEXT_PUBLIC_ | prefix ที่ทำให้ environment variable ถูกฝังเข้าไปใน client bundle ตอน build ต้อง access เป็น static literal เท่านั้น — `process.env.NEXT_PUBLIC_X` ห้ามใช้ `process.env[key]` — เพราะการแทนที่ค่านี้เป็นการแทนที่ string ตอน build ไม่ใช่การอ่านค่าตอน runtime | [Environment และ Configuration](/nextjs/th/production-and-ecosystem/environment-and-configuration/) |
| NextRequest / NextResponse | class ที่ต่อยอดจาก Request/Response มาตรฐาน ใช้ใน `proxy.ts` และ Route Handler — `NextRequest` เพิ่มความสะดวกอย่าง cookie helper, `NextResponse` เพิ่ม `.redirect()`, `.rewrite()`, และ `.next()` เพื่อให้ request เดินหน้าต่อโดยไม่แก้ไข (จะแนบ header ให้ Server Component ปลายทางอ่านต่อก็ได้) | [Proxy (Middleware) และ Request Lifecycle](/nextjs/th/production-and-ecosystem/middleware-and-the-request-lifecycle/) |
