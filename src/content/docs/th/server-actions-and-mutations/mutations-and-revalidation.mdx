## ไอเดียในหนึ่งประโยค

mutation คือ flow สี่ขั้น validate input, เขียนลง database, เรียก `updateTag`, `revalidateTag` หรือ `revalidatePath` เพื่อ refresh ข้อมูลที่ cache ไว้ซึ่งได้รับผลกระทบ และ redirect ถ้าจำเป็น เพื่อให้ UI สะท้อนการเปลี่ยนแปลงโดยไม่ต้อง reload เอง

## Flow ของ mutation แบบเต็ม

ภายใน action เรา validate ก่อน แล้วค่อย mutate แล้วค่อย revalidate ข้อมูลที่เพิ่งเปลี่ยน หลัง revalidate แล้วจึง redirect เพราะ `redirect` throw ภายในและหยุดโค้ดที่เหลือของ function ไม่ให้รันต่อ

```ts
// app/actions.ts — validate, write, revalidate, redirect
'use server'

import { revalidatePath } from 'next/cache'
import { redirect } from 'next/navigation'
import { z } from 'zod'

const schema = z.object({ title: z.string().min(1) })

export async function createPost(formData: FormData) {
  const parsed = schema.safeParse({ title: formData.get('title') })
  if (!parsed.success) {
    return { error: 'Invalid title' }
  }

  await db.post.create({ data: { title: parsed.data.title } })

  revalidatePath('/posts')
  redirect('/posts')
}
```

## updateTag, revalidateTag และ revalidatePath

`revalidatePath('/posts')` invalidate ทุกอย่างที่ cache ไว้สำหรับ route นั้น การ invalidate ด้วย tag ตรงจุดกว่าเมื่อข้อมูลเดียวกันโผล่ในหลาย route ให้ tag ตอน read แล้ว expire tag หลัง write ภายใน Server Action ให้ใช้ `updateTag('posts')` ซึ่ง expire tag ทันที request ถัดไปจึงรอข้อมูลใหม่และผู้ใช้เห็นสิ่งที่ตัวเองเพิ่งเขียน ส่วน `revalidateTag(tag, profile)` จะ mark tag ว่า stale และยังเสิร์ฟข้อมูลเก่าระหว่าง refresh เบื้องหลัง ใน Next.js 16 argument ตัวที่สอง `profile` เป็นค่าบังคับ (แบบ argument เดียวถูก deprecate และเป็น TypeScript error) และ `'max'` คือค่าที่แนะนำ ใช้ `revalidateTag` ใน Route Handler และ webhook ซึ่งเรียก `updateTag` ไม่ได้

```ts
// app/posts/data.ts — tag the read so you can revalidate by tag later
export async function getPosts() {
  const res = await fetch('https://api.example.com/posts', {
    next: { tags: ['posts'] },
  })
  return res.json()
}
```

```ts
// app/actions.ts — expire only the tagged data so the next request sees the write
'use server'

import { updateTag } from 'next/cache'

export async function publishPost(id: string) {
  await db.post.update({ where: { id }, data: { published: true } })
  updateTag('posts')
}
```

```ts
// app/api/revalidate/route.ts — outside a Server Action, use revalidateTag with a profile
import { revalidateTag } from 'next/cache'

export async function POST() {
  revalidateTag('posts', 'max')
  return Response.json({ revalidated: true })
}
```

## Client cache ถูก refresh อย่างไร

ส่วนนี้โยงกลับไปที่ caching module ฝั่ง server การ revalidate จะล้าง entry ใน Data Cache ของ fetch ที่ได้รับผลกระทบ ฝั่ง client response ของ Server Action ยัง refresh Client Cache ของ route ปัจจุบันด้วย segment ที่ render ไปแล้วจึงถูกแทนด้วย output ใหม่จาก server ผู้ใช้เห็นข้อมูลใหม่โดยไม่ต้อง hard reload cache ทั้งสองตัวจึงคงความ consistent
