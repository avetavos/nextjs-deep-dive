## ไอเดียในหนึ่งประโยค

ไฟล์ `proxy.ts` ที่ root ของโปรเจกต์จะรันก่อน request จะเสร็จ บนทุก route ที่ match ทำให้เรา redirect, rewrite หรือ set header กับ cookie ได้ก่อนที่ Next.js จะ render อะไรออกมา Next.js 16 เปลี่ยนชื่อไฟล์นี้จาก `middleware.ts` เป็น `proxy.ts`

## proxy อยู่ตรงไหนใน request lifecycle

proxy ดัก request หลังจาก request มาถึงแต่ก่อน route จะถูก resolve เรา export function ชื่อ `proxy` (หรือ default export) แล้ว return `NextResponse` เพื่อ redirect, rewrite หรือปล่อยผ่านด้วย `NextResponse.next()`

```ts
// proxy.ts — runs BEFORE the request completes, on every matching route
import { NextResponse } from 'next/server'
import type { NextRequest } from 'next/server'

export function proxy(request: NextRequest) {
  // Lightweight auth gate: redirect logged-out users away from /dashboard
  const isLoggedIn = request.cookies.has('session')
  if (request.nextUrl.pathname.startsWith('/dashboard') && !isLoggedIn) {
    return NextResponse.redirect(new URL('/login', request.url))
  }

  // Otherwise continue, and set a header on the way through
  const response = NextResponse.next()
  response.headers.set('x-request-time', Date.now().toString())
  return response
}
```

## จำกัดขอบเขตด้วย matcher

ถ้าไม่มี `matcher` proxy จะรันทุก request รวมถึง static asset ด้วย เราจึงควร scope ให้รันเฉพาะจุดที่ต้องการ config `matcher` รับ path pattern และ exclude ส่วน internal ได้

```ts
// proxy.ts — scope which routes run proxy
export const config = {
  matcher: ['/((?!api|_next/static|_next/image|favicon.ico).*)'],
}
```

## Redirect, rewrite และ Node.js runtime

ใช้ proxy สำหรับ redirect, rewrite (URL เดิมแต่เสิร์ฟ content ต่างกัน) และ set header หรือ cookie การ rewrite เสิร์ฟ content คนละแบบโดยไม่เปลี่ยน URL บน browser เหมาะกับ A/B test หรือ geo routing

```ts
// A/B or geo rewrite — same URL, different content served
import { NextResponse } from 'next/server'
import type { NextRequest } from 'next/server'

export function proxy(request: NextRequest) {
  const country = request.headers.get('x-vercel-ip-country') ?? 'us'
  return NextResponse.rewrite(new URL(`/${country}${request.nextUrl.pathname}`, request.url))
}
```

proxy รันบน Node.js runtime เสมอและเปลี่ยนไม่ได้ ถ้า export `runtime` จาก `proxy.ts` จะ build ไม่ผ่าน แต่มันยังอยู่หน้าทุก request ที่ match เพราะฉะนั้นต้องเร็ว ไม่ยิง database ไม่คำนวณหนัก ไม่ใช้ dependency ใหญ่ ตัดสินใจเบา ๆ ตรงนี้แล้วโยนงานจริงไปที่ route

<Callout title="middleware.ts ถูก deprecate แล้ว">
ไฟล์ `middleware.ts` และ `export function middleware` แบบเดิมยังใช้ได้ใน Next.js 16 แต่ `next build` จะพิมพ์ deprecation warning ออกมา migrate ด้วย `npx @next/codemod@canary middleware-to-proxy .` ซึ่งจะเปลี่ยนชื่อทั้งไฟล์และ function ให้ เหตุผลเดียวที่จะเก็บ `middleware.ts` ไว้คือถ้ายังต้องใช้ Edge runtime (ซึ่งถูก deprecate เช่นกัน)
</Callout>
