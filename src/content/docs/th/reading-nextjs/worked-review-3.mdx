## ฟีเจอร์นี้คืออะไร

โจทย์ที่ให้ AI คือ: *"สร้างแคตตาล็อกสินค้าที่มี grid, หน้าสินค้าแต่ละชิ้น, และปุ่ม Add to cart"* โปรเจกต์นี้เปิด `cacheComponents: true` เช่นกัน และหน้าสินค้าควรถูก prerender ตอน build — เว็บอีคอมเมิร์ซจริงรับไม่ไหวถ้าต้องมี server round trip ต่อผู้เยี่ยมชมหนึ่งคนสำหรับหน้าที่แทบไม่เปลี่ยนแปลง อ่านตาม[ลำดับการอ่าน](/nextjs/th/reading-nextjs/index/)เดียวกับสองรีวิวแรก: boundary ก่อน แล้วค่อย routing แล้วค่อย caching model แล้วค่อยรายละเอียดด้าน optimization ที่เว็บช็อปปิ้งอยู่หรือตายเพราะมัน โค้ดชุดนี้มี **bug จริง 6 จุด** และ `next build` จับได้ตรงๆ ถึง 4 จุด

## เดินรีวิวทีละจุด

### Boundary: `ssr: false` ส่งให้ `next/dynamic` ข้างใน Server Component

`recently-viewed.tsx` ไม่มี directive `'use client'` เลย — มันคือ Server Component — และมันเรียก `dynamic(() => import(...), { ssr: false })`

<SpotTheBug code={`import dynamic from 'next/dynamic'

const RecentlyViewedWidget = dynamic(() => import('./recently-viewed-widget'), { ssr: false })

export function RecentlyViewed() {
  return <RecentlyViewedWidget />
}`}>
`ssr: false` แปลว่า "ห้าม render สิ่งนี้บนเซิร์ฟเวอร์เลย" — เป็นคำขอที่มีแค่ Client Component เท่านั้นที่ทำได้กับตัวเอง เพราะ Server Component ไม่มีทางเลือกฝั่ง client ให้ fallback กลับไปได้ build ไฟล์นี้เป๊ะๆ ล้มเหลวทันที:

```text
Error: Turbopack build failed with 1 error:
./app/products/[id]/recently-viewed.tsx:4:20
Error: `ssr: false` is not allowed with `next/dynamic` in Server Components. Please move it into a Client Component.
```

วิธีแก้ที่ข้อความ error ของ Next.js เองบอกไว้ก็คือคำตอบที่ถูกต้อง: เพิ่ม `'use client'` ไว้บนสุดของไฟล์นี้ ตัวเลือก `ssr: false` ของ `next/dynamic` จะกลายเป็นคำขอที่ framework ทำตามได้จริง เพราะทั้งโมดูลเป็น client-only อยู่แล้ว
</SpotTheBug>

### Routing: `<a>` ธรรมดาสำหรับ route ภายใน

grid สินค้าลิงก์ไปแต่ละหน้าสินค้าด้วย `<a href={...}>` แทนที่จะเป็น `<Link>`

<SpotTheBug code={`<a key={p.id} href={\`/products/\${p.id}\`}>
  <div style={{ position: 'relative', height: 200 }}>
    <Image src={p.image} alt={p.name} fill style={{ objectFit: 'cover' }} />
  </div>
  <p>{p.name}</p>
</a>`}>
`<a>` ธรรมดาก็ยัง navigate ได้ — นี่คือเหตุผลที่ bug นี้พลาดง่ายมากตอนดูผ่านๆ build แล้วคลิกใน browser จริง ความต่างจะปรากฏใน network log ไม่ใช่ที่ว่าหน้าเว็บทำงานหรือไม่ คลิก `<Link href="/products/1">` ในหน้าเดียวกันจะได้ request เล็กๆ สองอันที่มี query parameter `_rsc` และไม่มีอะไรอื่นเลย:

```text
GET /products/1?_rsc=rq0KtoLEX-G_daAz -> 200
GET /products/1?_rsc=Uj6tDUbDhWjKIlIB -> 200
```

คลิก `<a href="/products/2">` ธรรมดาแทน จะได้ full document request ที่ไม่มี parameter `_rsc` เลย ตามด้วยทุก static asset — font, CSS, ทุก JS chunk — โหลดใหม่ทั้งหมดตั้งแต่ต้น เหมือนกับตอนโหลดหน้าครั้งแรกเป๊ะ:

```text
GET /products/2 -> 200   (a full navigation, not an RSC fetch)
GET /_next/static/media/797e433ab948586e-s.p.0r6juujl39pe6.woff2 -> 200
GET /_next/static/chunks/3n8-9sbopjxwd.css -> 200
GET /_next/static/chunks/3s6nzrbk-8mnv.js -> 200
... (every other static chunk, re-downloaded)
```

วิธีแก้คือ `<Link href={...}>` จาก `next/link` — หน้าตาและการทำงานเหมือนกันทุกประการสำหรับผู้ใช้ที่ไม่เคยเปิด network panel เลย แต่มันข้ามการ reload หน้าทั้งหมดและการโหลด asset ที่ browser มีอยู่แล้วซ้ำ
</SpotTheBug>

### Caching model: `generateStaticParams` ที่ว่างเปล่า

`generateStaticParams` บนหน้าสินค้าคืนค่า `[]`

<SpotTheBug code={`export async function generateStaticParams() {
  return []
}`}>
ภายใต้ Cache Components `generateStaticParams` ที่ว่างเปล่าไม่ใช่แค่ "ไม่มีหน้าไหนถูก prerender" — มันคือ build error ตรงๆ เพราะ framework ไม่สามารถทำ build-time validation ได้อีกต่อไปว่าไม่มีอะไร dynamic รั่วผ่านมาสำหรับชุด param ที่มันไม่เคยเห็นเลย:

```text
Error: When using Cache Components, all `generateStaticParams` functions must return at least one result. This is to ensure that we can perform build-time validation that there is no other dynamic accesses that would cause a runtime error.

Learn more: https://nextjs.org/docs/messages/empty-generate-static-params
```

วิธีแก้คือคืนค่าชุด param จริงๆ — `listProducts()` มีอยู่แล้วในโค้ดชุดนี้เองสำหรับหน้า grid `generateStaticParams` แค่ต้อง map มันเป็น object `{ id }` เหมือนที่บท[static และ dynamic rendering](/nextjs/th/rendering/static-and-dynamic-rendering/)แสดงไว้สำหรับกรณีทั่วไป
</SpotTheBug>

### Caching model: `export const runtime = 'edge'` อยู่ข้างๆ `cacheComponents`

หน้าสินค้ายัง export `runtime = 'edge'` ด้วย

<SpotTheBug code={`export const runtime = 'edge'`}>
นี่คือความล้มเหลวหมวดเดียวกับที่บท[route segment config](/nextjs/th/rendering/route-segment-config-and-runtimes/)พิสูจน์ไว้สำหรับ route segment config export ทุกตัว — `runtime` ถูกปฏิเสธภายใต้ Cache Components ไม่ว่าค่าจะเป็นอะไร ไม่ใช่แค่ `'edge'` เพราะ Cache Components ต้องการ Node.js runtime และไม่มีอะไรให้ config เหลืออยู่แล้ว:

```text
Error: Turbopack build failed with 1 error:
./app/r3b5/page.tsx:2:14
Error: Route segment config "runtime" is not compatible with `nextConfig.cacheComponents`. Please remove it.
```

วิธีแก้ก็แค่ลบ export นี้ทิ้ง ไม่ต้องมีตัวแทนใดๆ เลย — Node.js runtime ค่า default คือตัวเดียวที่ Cache Components รองรับ
</SpotTheBug>

### Optimization: `next/image` ที่ใช้ `fill` โดยไม่มี `sizes`

ทั้งรูป thumbnail ใน grid และรูปในหน้ารายละเอียดสินค้าใช้ `fill` โดยไม่มี prop `sizes`

<SpotTheBug code={`<div style={{ position: 'relative', width: 400, height: 400 }}>
  <Image src={product.image} alt={product.name} fill style={{ objectFit: 'cover' }} />
</div>`}>
เมื่อไม่มี prop `sizes` Next.js จะตั้งค่า default ของรูป `fill` เป็น `sizes="100vw"` — เท่ากับบอก browser ว่ารูปนี้กว้างเท่า viewport ไม่ว่ากล่องจริงจะเล็กแค่ไหน build หน้า grid แล้วอ่าน HTML ที่ render ออกมา จะเห็นต้นทุนที่แท้จริง: ด้วย grid cell กว้าง 300px และไม่มี `sizes` browser เลือก candidate ที่กว้าง **640px** — ตัวที่เล็กที่สุดที่ "ครอบคลุม" viewport 400px เต็มภายใต้สมมติฐาน `100vw`:

```text
sizes="100vw"
srcSet="/_next/image?url=%2Fproduct.png&w=640&q=75 640w, ... up to ... &w=3840&q=75 3840w"
```

วิธีแก้คือค่า `sizes` ที่ตรงกับความกว้างที่ render จริง: `sizes="(max-width: 768px) 100vw, 33vw"` สำหรับ grid cell ที่กว้างประมาณหนึ่งในสาม และ `sizes="400px"` แบบตายตัวสำหรับรูปในหน้ารายละเอียดสินค้าที่มีขนาดคงที่ เมื่อ build พร้อมวิธีแก้แล้ว รูปในหน้ารายละเอียดสินค้าจะขอ candidate ขนาด 400px แทนที่จะเป็นตัวที่ใหญ่ที่สุดใน `deviceSizes`
</SpotTheBug>

### Optimization: `viewport` อยู่ข้างใน `metadata`

`generateMetadata` ตั้ง `viewport` เป็น field ใน object `Metadata` ที่คืนค่า

<SpotTheBug code={`export async function generateMetadata({
  params,
}: {
  params: Promise<{ id: string }>
}): Promise<Metadata> {
  const { id } = await params
  const product = await getProduct(id)
  return {
    title: product?.name ?? 'Product',
    viewport: 'width=device-width, initial-scale=1',
    openGraph: { images: [product?.image ?? '/product.png'] },
  }
}`}>
`viewport` เคยเป็น field ของ `metadata` ใน Next.js เวอร์ชันเก่า วันนี้มันเป็น export ของตัวเอง (`viewport` หรือ `generateViewport`) การใส่มันไว้ข้างใน `metadata` ไม่ทำให้เกิด error — มันแค่ถูกทิ้งไป พร้อม warning ที่พลาดดูง่ายมากใน build log ยาวๆ:

```text
⚠ Unsupported metadata viewport is configured in metadata export in /r3b3. Please move it to viewport export instead.
Read more: https://nextjs.org/docs/app/api-reference/functions/generate-viewport
```

ผู้เยี่ยมชมทุกคนบนมือถือจะได้พฤติกรรม viewport ค่า default ของ browser (ปกติไม่ responsive) แทนที่จะเป็นค่าที่โค้ดนี้ตั้งใจจะตั้งไว้อย่างชัดเจน วิธีแก้คือ export คู่กัน `export const viewport: Viewport = { width: 'device-width', initialScale: 1 }` ใน root layout — ตั้งครั้งเดียวแล้วใช้กับทุกหน้า รวมถึงหน้านี้ด้วย
</SpotTheBug>

```tsx
import { addToCart } from './actions'
import { RecentlyViewed } from './recently-viewed'

  return products.map((p) => ({ id: p.id }))

    openGraph: { images: [product?.image ?? '/product.png'] },

// is required under cacheComponents, and 'edge' is deprecated regardless.
export default async function ProductPage({ params }: { params: Promise<{ id: string }> }) {
  const { id } = await params
  const product = await getProduct(id)
  if (!product) return <p>Not found</p>

      <p><Link href="/products">Back to products</Link></p>
      <h1>{product.name}</h1>
      <div style={{ position: 'relative', width: 400, height: 400 }}>

      </div>
      <p>${(product.price / 100).toFixed(2)}</p>
      <form action={addToCart.bind(null, product.id)}>
        <button type="submit">Add to cart</button>
      </form>
      <RecentlyViewed />
```

```text
  └ ○ /products/3
```

start เซิร์ฟเวอร์ที่ build แล้วและยิง request ไปที่หน้าสินค้าจริง ยืนยันการแก้ทุกจุดตั้งแต่ต้นจนจบ: og:image ที่ resolve ออกมาเป็น URL production จริงแบบ absolute (ไม่ใช่ `localhost`), รูปทั้งใน grid และหน้ารายละเอียดขอ candidate ขนาดที่เหมาะสม, ลิงก์สินค้าใน grid เป็น `<a>` จริงที่ render โดย `<Link>` (navigate ฝั่ง client ได้), widget ที่รันฝั่ง client เท่านั้น render ถูกต้อง, และ cart action log บนเซิร์ฟเวอร์พอดีหนึ่งครั้งต่อการคลิกหนึ่งครั้ง:

```text
<meta property="og:image" content="https://shop.example.com/product.png"/>
sizes="400px"                                    (product detail image)
sizes="(max-width: 768px) 100vw, 33vw"           (grid thumbnails, ×3)
<a href="/products/1">                           (rendered by <Link>)
"Recently viewed: none yet"                      (client-only widget, correctly client-rendered)
server log: added to cart 1
```

## สิ่งที่เปลี่ยนและเหตุผล

| # | Bug | หมวด | วิธีแก้ |
|---|---|---|---|
| 1 | `dynamic(..., { ssr: false })` ข้างใน Server Component | Boundaries | เพิ่ม `'use client'` ให้ไฟล์ที่เรียก `dynamic()` |
| 2 | `<a href={...}>` สำหรับ route ภายใน | Routing | `<Link href={...}>` จาก `next/link` |
| 3 | `generateStaticParams` คืนค่า `[]` | Caching model | คืนค่าชุด param จริงจาก `listProducts()` |
| 4 | `export const runtime = 'edge'` อยู่ข้างๆ `cacheComponents` | Caching model | ลบ export ทิ้ง — Node.js คือ runtime เดียวที่รองรับ |
| 5 | `next/image` ใช้ `fill` โดยไม่มี `sizes` | Optimization | ค่า `sizes` ที่ตรงกับความกว้างที่ render จริง |
| 6 | `viewport` เป็น field ข้างใน `metadata` | Optimization | `export const viewport: Viewport` แยกต่างหาก |

## Mental Model

สี่ในหก bug ของรีวิวนี้เป็นข้อเท็จจริงตอน build ที่ `next build` ปฏิเสธตรงๆ อยู่แล้ว — `ssr: false` ข้างใน Server Component, `generateStaticParams` ที่ว่างเปล่า, และ `runtime` ภายใต้ Cache Components ล้วนล้มเหลวดังๆ ใน build เดียวกัน อีกสองจุด — `<a>` ธรรมดา และ `sizes` ที่หายไป — build ผ่านสะอาดหมดจด และมีต้นทุนจริงก็ต่อเมื่อ browser ของผู้เยี่ยมชมโหลดหน้านั้นจริงๆ: การ reload หน้าทั้งหมดแทนที่จะเป็นการ navigate ฝั่ง client แบบทันที และข้อมูลรูปภาพหลายเท่าตัวเกินกว่าที่ layout ต้องการ ทั้งสองอย่างไม่ปรากฏจากการอ่าน JSX เลย แต่ปรากฏใน network panel ทั้งคู่

## ความเข้าใจผิดที่พบบ่อย

- **"`ssr: false` เป็นแค่ hint ด้าน performance ที่คอมโพเนนต์ไหนก็ใช้ได้"** มันคือคำขอที่มีแค่ Client Component เท่านั้นที่ทำได้กับตัวเอง — Server Component ไม่มี client fallback ให้ opt out *ไปหา*
- **"`generateStaticParams` ที่ว่างเปล่าแปลว่า `next build` แค่ข้ามการ prerender เหมือนเดิม"** ภายใต้ Cache Components โดยเฉพาะ มันคือ build error ตรงๆ ไม่ใช่ no-op เงียบๆ — framework ต้องการ param อย่างน้อยหนึ่งตัวเพื่อ validate
- **"`<a>` ธรรมดาสำหรับลิงก์ภายในก็ยังใช้งานได้ แปลว่าไม่ใช่ bug จริง"** มัน navigate ได้ถูกต้อง นี่แหละคือเหตุผลที่มันรอดจาก code review — ต้นทุนปรากฏก็ต่อเมื่อดูใน network panel เป็นการ reload ทั้งหมดและโหลด static asset ทุกตัวซ้ำ
